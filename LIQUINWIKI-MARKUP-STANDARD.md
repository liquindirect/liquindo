# LiquinWiki Markup Standard (LMS)

LMS is the shared, backward-compatible article format used by the public LiquinWiki renderer and markup editor. Existing stored article HTML and existing MediaWiki-like markup remain supported. The renderer sanitizes its output before display. This standard does not require a database migration or rewriting existing article records.

## Supported syntax

- Headings: == Section ==, === Subsection ===, through level 6.
- Bold / italic / strike: '''bold''', ''italic'', ~~deleted~~.
- Internal links: [[Article title]] or [[Article title|label]].
- External links: [https://example.com label].
- Lists: * item, # item, including nested markers.
- Quotations: prefix a line with a space.
- Horizontal rule: ----.
- Images: [[File:https://example.com/image.jpg|right|300px|alt=Description|Caption]]. Alignment may be left, right, or center; widths are constrained to safe bounds.
- Galleries: start with <gallery> or {{Gallery, add one image URL per line (optionally followed by | caption), and close with </gallery> or }}.
- Infoboxes: {{Infobox type, followed by | label = value rows, then }}.
- Tables: MediaWiki-style {| class="wikitable", |-, !, |, and |}.
- References: <ref>Source details</ref>; named references may be reused with <ref name="source" />. A references list is generated automatically.
- Categories: [[Category:Name]].
- Existing patterns: redirects, short descriptions, see-also notices, and disambiguation notices.

## Rendering and editing rules

1. Published articles and editor previews use the same renderer module.
2. Article body copy, list items, table cells, captions, and infobox text use a universal 16px base size. Headings retain a deliberate hierarchy.
3. Images never set the font size of adjacent article text; image floats become centred blocks on narrow screens.
4. Tables remain readable and scroll horizontally on narrow screens.
5. The existing heading-derived table of contents remains automatically generated by the article page.
6. Markup validation checks unclosed blocks, unsafe script patterns, suspicious image URLs, malformed headings, and unresolved named-reference uses. Warnings are non-blocking after explicit confirmation; structural/security errors block submission.
7. Validation does not rewrite article source. Existing article rows, slugs, IDs, revision history, roles, approval rules, and article status are unchanged.

## Compatibility and deployment

- No Supabase schema or data migration is required.
- Do not normalize or bulk-update existing wiki_pages or wiki_revisions.
- Keep the renderer version query string synchronized in wiki-public.js and wiki-editor.js.
- The shared stylesheet is loaded by both wiki.html and wiki-editor.html.
- Test a legacy HTML article, a markup article, a large image, a gallery, an infobox, a wide table, a named reference, and mobile rendering before merging.
